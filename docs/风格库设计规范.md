# 风格库设计规范

> **v4.0 风格基因卡设计原则和规范**

---

## 设计理念

### 核心原则

**风格是基因，不是模板**

- ❌ 错误：模仿具体创作者的口头禅
- ✅ 正确：提取可观察的风格特征

**风格可组合，不冲突**

- ❌ 错误：每种风格都是独立的、完整的输出
- ✅ 正确：风格是维度，可叠加组合

**风格抽象，可复用**

- ❌ 错误：针对具体话题的风格
- ✅ 正确：跨话题通用的风格特征

## 风格DNA设计指南

### 1. Tone (语气)

**好的语气描述**：
```
✅ "清晰、兴奋、未来感、强类比"
✅ "对话式、好奇、深入、不评判"
✅ "犀利、直接、讽刺但有干货"
```

**不好的语气描述**：
```
❌ "很好"
❌ "专业"
❌ "像某某博主"
```

### 2. Sentence Rhythm (句式节奏)

**好的节奏描述**：
```
✅ "短句开场，中句解释，结尾升维"
✅ "提问停顿，倾听回应，追问深挖"
✅ "金句密集，短促有力"
```

**不好的节奏描述**：
```
❌ "有节奏感"
❌ "流畅"
```

### 3. Vocabulary (词汇特征)

**好的词汇描述**：
```
✅ "科技词汇 + 日常类比"
✅ "商业术语 + 网络热词适度混合"
✅ "专业词汇，配简单解释"
```

### 4. Hook Patterns (钩子模式)

**好的钩子模式**：
```yaml
hook_patterns:
  - "一个新技术正在改变普通人的工作方式"
  - "多数人只看到工具，高手已经在重构流程"
  - "这可能是近年来最重要的技术趋势"
```

**设计原则**：
- ✅ 具体而非抽象
- ✅ 可跨话题复用
- ✅ 有明确结构

### 5. Logic Patterns (逻辑模式)

**好的逻辑模式**：
```yaml
logic_patterns:
  - "现象 → 案例 → 机制 → 商业机会"
  - "旧方法低效 → 新工具放大 → 个体套利窗口"
  - "问题诊断 → 解决方案 → 行动建议"
```

## 新风格卡添加流程

### 1. 确定分类

```yaml
# 选择合适分类
category: "tech_business"  # 或其他
region: "global"          # 或 china
```

### 2. 分析风格特征

观察目标创作者/内容类型，提取：
- 语气特征
- 句式节奏
- 词汇选择
- 常用钩子
- 逻辑结构

### 3. 编写风格卡

```yaml
- id: tech_storyteller
  label: "科技故事讲述者"
  category: "tech_creator"
  region: "global"

  style_dna:
    tone: "叙事性强，情感丰富"
    sentence_rhythm: "场景开场 → 人物引入 → 冲突展现 → 结局升华"
    vocabulary: "科技词汇 + 叙事元素"

  hook_patterns:
    - "在一个平凡的下午，一切都改变了..."
    - "你可能不会相信，但这件事真的发生了"

  logic_patterns:
    - "场景引入 → 人物冲突 → 技术转折 → 启示总结"
```

### 4. 测试验证

```python

mixer = StyleMixer()

# 生成测试内容

```

### 5. 提交审核

创建 Pull Request，包含：
- 新风格卡
- 测试结果
- 使用示例

## 常见问题

### Q1: 如何确保风格不侵权？

**A**: 遵循以下原则：
1. 只描述可观察的特征
2. 不复制具体表达
3. 不使用个人专属口头禅
4. 添加引用水平说明

### Q2: 风格太多怎么办？

**A**:
1. 使用分类系统
2. 提供风格推荐
3. 支持风格搜索
4. 热门风格优先

### Q3: 如何更新已有风格？

**A**:
1. 提交 Issue 说明更新理由
2. 创建 PR 包含更改
3. 提供测试结果
4. 等待审核合并
